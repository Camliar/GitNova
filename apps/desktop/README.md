# Desktop Host

Tauri 2 + React 19 Desktop Host. This package owns the native window, presentation, accessibility, and the lifecycle and byte transport for a separate `gitnova-core` process.

The Tauri layer starts Core directly, completes the protocol handshake, transports framed JSON-RPC requests, and guarantees child cleanup. The React shell displays the real connection state and an explicit retry action. It intentionally contains no Git, GitHub, PR, diff, or Squash Trace business logic. See [Desktop Core Transport](../../docs/DESKTOP_CORE_TRANSPORT.md).

Before Core starts, Desktop can select the bundled local sidecar or a structured WSL, batch-mode SSH, or Dev Container launcher. Remote paths are entered as seen by Core and remain opaque to Desktop. See [Remote Core Environments](../../docs/REMOTE_ENVIRONMENTS.md).

The first end-to-end Desktop slice lets the user choose one directory with the native dialog and sends that opaque path to Core's `repository/open`. Repository kind, roots, Git directory, and Git version shown by the Host are protocol facts returned by Core. Desktop does not scan for repositories, inspect `.git`, or run Git. Dialog access is limited to the main window's open-dialog permission and does not grant general filesystem access.

After a non-bare repository opens, Desktop requests one `repository/status` snapshot and renders the Core-provided branch, upstream divergence, and ordered changes. Staged and working-tree states remain separate, including untracked, rename/copy, and conflict entries. Refresh is explicit: there is no watcher or polling, and this read-only slice cannot stage, discard, or modify files. Bare repositories are identified before the request and show that no working tree is available.

Local Changes projects the Core snapshot into separate Unstaged and Staged lists. A mixed-status path appears in both lists and clicking its file name opens that exact scope, so no redundant View button or scope badge is required. Desktop sends the Core-provided repository-relative path and selected scope to `repository/diff`, then renders structured hunks, old/new line numbers, binary, and empty results. Repository-controlled line content is inserted only as text. Untracked content is labeled but not made actionable because Core does not read or synthesize it, and refreshing status closes any previously selected diff.

Desktop also requests the Core-owned `repository/graph` projection after any repository opens, including bare repositories. The compact timeline renders graph lanes, commit message, refs, author, short SHA and timestamp in one selectable row exactly as projected by Core. Pages contain 30 commits and advance only through the opaque `nextCursor`; the Host never parses or persists it. Incremental failures retain already loaded commits and can be retried independently from working-tree status.

Each 28 px timeline row first opens commit metadata and an ordered file list through `repository/commitFiles`. Root and single-parent commits use Core's automatic comparison rules; merge commits require the user to choose one displayed direct parent before any request is sent. The lower pane separates Commit metadata from Changes; clicking a file loads only its line diff through `repository/commitFileDiff`. A zero-file result is labeled as an empty commit whose tree matches the comparison baseline, distinctly from a request failure. Closing or replacing a selection invalidates pending responses, while per-file errors retain the timeline, metadata, file list, and exact comparison for retry. Older Cores fall back to `repository/commitDiff` through capability negotiation.

GitHub access remains off after repository open. The user must explicitly choose Connect GitHub before Desktop asks Core for normalized repository metadata. Once connected, a positive PR number triggers `github/pullRequest` for that exact `nameWithOwner`; Desktop renders normalized PR metadata and the complete ordered original commit list. It never invokes `gh`, requests a token, navigates provider URLs, retries automatically, or fetches per-commit remote diffs in this slice.

From a selected local history commit, **Check Squash Trace** explicitly asks Core to find a merged PR whose Provider merge OID exactly matches the full local OID. No match and Core-classified ordinary merge/rebase relationships keep Commit/Changes unchanged. A `squashCandidate` opens a compact ordered original-commit list and relationship summary; selecting an original loads only file metadata, then clicking a file requests only its patch from Core's bounded memory cache. Desktop never parses PR hints, classifies merge topology, or receives every cached patch at once.

An original commit row can explicitly request its Core-validated `github/pullRequestCommitDiff`. Desktop renders Provider file statistics and structured patches; unavailable patches remain unknown rather than being labeled binary. The request cannot be used for an OID outside the displayed PR membership.

The repository workbench separates Local Changes, All Commits, Pull Requests and Settings instead of rendering every feature as one page. Local Changes uses staged/unstaged lists beside a large diff and a compact bottom commit composer. All Commits keeps a 28-pixel graph/ref/message/author/SHA/time row in the upper pane and tabbed context below; the selected row uses a single full-width highlight. Provider data appears there only after explicit Squash Trace actions. Repository identity appears once in a stable tab strip rather than being repeated in the sidebar.

After successful opens, Desktop keeps a bounded, stable-order tab list containing only opaque repository paths and structured Core launch targets as a local Host preference. The active tab selects one repository; Add repository and the tab-strip `+` append another entry without reordering existing tabs. Because Core intentionally owns only one active repository per process, switching tabs cleanly restarts Core in the saved target before repeating `repository/open`; it does not run parallel Core sessions or duplicate repository logic in React. On the next launch Desktop restores the last active tab automatically. The previous single-repository preference migrates automatically, and a failed add or switch restarts and reopens the previous target before restoring its active tab where possible.

The left Branches/Remotes/Tags tree is the only branch context surface; the current local branch is emphasized there. Right-click or the keyboard-focusable actions button opens only operations supported by that exact ref. Selecting a different local branch confirms `repository/switchBranch`; selecting a non-symbolic remote branch confirms `repository/checkoutRemoteBranch`, which creates a direct tracking local branch after Core revalidates the opaque full ref, local-name availability, and the confirmed HEAD. Tags and symbolic remote HEAD remain informational. Core never auto-stashes, forces, resets, or discards changes. A successful switch refreshes status, history, refs, and clears stale detail selections.

When Core advertises `repositorySync`, the top toolbar adds Fetch, Pull and Push for an attached non-bare worktree. Fetch is an explicit one-click network action. Pull and Push show branch plus confirmed HEAD before execution; Pull is disabled without upstream and Core permits fast-forward only, while Push sends only the confirmed OID to the tracked or same-name `origin` branch without force. Success applies Core's snapshot and refreshes history; failures preserve the workspace and expose an explicit retry.

When Core advertises `aiAssist`, Settings owns Provider/model/endpoint/exclusion configuration. Only the commit composer exposes a default-collapsed AI generation action; history and PR views do not render it. Desktop then renders Core's offline disclosure preview and never receives an API key, prompt, or raw patch. External OpenAI generation requires a preview-specific checkbox, while local Ollama still requires a button click. Configuration changes invalidate all prior consent and results. The editable draft can be copied into the existing commit form, but `repository/commit` remains behind its separate Review/Confirm flow.

Native `core_request` accepts an explicit Host method allowlist. AI and repository sync methods are included, while lifecycle calls and arbitrary method strings cannot cross the Tauri bridge. Remote Git/Provider actions and AI generation receive separate longer bounded transport timeouts than local read requests.

Run `pnpm --filter @gitnova/desktop check`, `test`, or `build` from the repository root. Debug and test builds may select an absolute Core executable with `GITNOVA_CORE_BINARY`; release builds resolve the bundled Core sidecar beside the Desktop executable. `npm run bundle:desktop` prepares that target-qualified sidecar before invoking Tauri bundling.

Native configuration lives in `src-tauri`. Its default capability grants only Tauri core window/event functionality; no shell, network, filesystem, or process plugin is enabled.
